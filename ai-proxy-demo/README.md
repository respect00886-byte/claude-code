# ai-proxy-demo（AIを安全に使う「中継役」の練習）

本物のAIにはつながず、**ダミーのAI**（いつも決まった返事をする係）を使って、
アプリからAIを安全に使うための「仕組み」だけを学ぶ見本です。

## 仕組み

```
ブラウザ（画面）  ──文章だけ──▶  中継役（サーバー）  ──文章＋合鍵──▶  AI
                ◀──返事だけ──                     ◀────返事────
```

- **ブラウザは合鍵を持ちません。** ブラウザの中身は、使う人なら誰でも覗けるからです。
- 合鍵を持つのは**中継役だけ**。中継役が文章をチェックしてから、代わりにAIへ頼みます。
- お店にたとえると、お客様（ブラウザ）は倉庫の鍵を持たず、店員（中継役）に頼んで商品を出してもらう形です。

## 3つの守り

| 守り | 何をする？ | なぜ必要？ |
| --- | --- | --- |
| ① 合鍵を隠す | 合鍵はファイルに書かず、起動するときに「環境変数」（そのパソコンに一時的に覚えさせる設定）で渡す。返事にもログ（動作の記録）にも出さない。万一まぎれ込んでも `****` に置きかえる | 合鍵が漏れると、他人に勝手に使われて料金を請求される |
| ② 文字数の上限 | 1回 **200文字** まで | 本物のAIは文字数で料金がかかる。長文を大量に送られると高くつく |
| ③ 1日の回数の上限 | 1日 **20回** まで（日本時間で日付が変わると0に戻る） | 何度も連打されて使いすぎるのを防ぐ |

ほかにも次の工夫をしています。
- 合鍵がないときやAIでエラーが起きたときは「準備ができていません」など**短い言葉だけ**返し、内部の事情は見せない
- このパソコンの中からだけ接続できるようにしている（外の人は使えない）

上限の数は `src/limits.js` で変えられます。

## 動かし方

Node.js 22 以上が必要です。追加のインストールは不要です。

```bash
cd ai-proxy-demo
AI_API_KEY=てきとうな文字 npm start
```

ブラウザで http://localhost:3000 を開きます（ダミーのAIなので、合鍵はどんな文字でも動きます）。
`AI_API_KEY=…` を付けずに起動すると、「準備ができていません」と安全に断ることを確かめられます。

## テスト

```bash
cd ai-proxy-demo
npm test
```

確かめていること：
- 合鍵が返事やログに含まれない（AIが合鍵入りの返事をしても外に出ない）
- 200文字を超えると断られる
- 1日20回を超えると断られる（次の日には戻る）
- 合鍵が設定されていないときは安全なエラーになる

## ファイル

| ファイル | 役割 |
| --- | --- |
| `server.js` | 窓口。画面を表示し、`/api/ask` で文章を受け取る |
| `src/proxy.js` | 中継役の本体（3つの守りのチェック） |
| `src/limits.js` | 上限の数と、1日の回数を数える係 |
| `src/dummyAi.js` | ダミーのAI |
| `public/index.html` | 画面 |
| `test/proxy.test.js` | テスト |

## 練習用なので省いていること

本番で使うなら、次も必要になります。
- 回数を人ごとに数える（今はサーバー全体で20回。サーバーを止めると0に戻る）
- ログインなどで「誰が使っているか」を確かめる
- 本物のAIにつなぐ部分（`src/dummyAi.js` を差し替える）
